## 4. 代理配置 — 请求打向后端的哪个地址

📄 [vite.config.js](./vite.config.js)

```js
export default defineConfig({
  server: {
    port: 3000,                        // 前端服务端口
    proxy: {
      '/api': {
        target: 'http://localhost:8080',   // ← /api/* 转发到后端 8080
        changeOrigin: true
      },
      '/uploads': {
        target: 'http://localhost:8080',   // ← 静态资源路径
        changeOrigin: true
      }
    }
  }
})
```

**核心结论（后端开发记住这句话）：**
> 前端代码里写的 `http.get('/user/me')`，经过 baseURL 变成 `/api/user/me`，再经过 Vite 代理，最终发到后端：
> **`POST / GET / PUT / PATCH / DELETE  http://localhost:8080/api/xxx`**

如果你的后端跑在别的端口或地址，改 `target` 就行。

## 5. API 接口清单 — 后端对照写接口

📄 [src/api/index.js](./src/api/index.js)

这个文件就是 **全部后端接口的前端调用清单**。直接在这个文件里搜索 `http.` 就能看到所有接口。

### 5.1 请求封装（axios 实例）

```js
const http = axios.create({
  baseURL: '/api',       // 所有请求自动加 /api 前缀
  timeout: 15000         // 15 秒超时
})
```

### 5.2 请求拦截器（自动带 Token）

```js
http.interceptors.request.use(config => {
  const t = getToken()
  if (t) {
    config.headers = config.headers || {}
    config.headers.Authorization = `Bearer ${t}`   // ← JWT 标准格式
  }
  return config
})
```

**后端需要做的：** 从请求头 `Authorization: Bearer <token>` 里解析出用户身份。

### 5.3 响应拦截器（统一错误处理）

```js
http.interceptors.response.use(
  res => {
    const data = res.data
    if (data && typeof data === 'object' && 'code' in data) {
      if (data.code !== 200) {
        return Promise.reject(data)   // code != 200 → 前端认为失败
      }
    }
    return res
  },
  err => {
    if (err.response && err.response.status === 401) {
      clearAuth()                      // HTTP 401 → 前端清 token，跳登录
      window.location.href = '/login'
    }
    return Promise.reject(err)
  }
)
```

**后端返回码要注意：**
- `code === 200` → 前端认为成功
- 其他 `code` → 前端认为失败，走 `.catch`
- `HTTP 401` → 前端自动退出登录并跳转登录页

### 5.4 统一响应包装函数 `ok()`

```js
function ok(res) {
  const raw = res.data
  if (raw && typeof raw === 'object' && 'code' in raw) {
    return { code: raw.code, msg: raw.msg || '', data: raw.data == null ? null : raw.data }
  }
  return { code: 200, msg: '', data: raw }
}
```

**后端接口的标准返回格式（重要！）：**

```json
{
  "code": 200,
  "msg": "成功",
  "data": { ... }
}
```

- `code`：业务状态码，`200` 代表成功
- `msg`：消息文本，成功时可为空
- `data`：业务数据，可为 `null`、对象、数组

## 12. Token 管理 & 认证流程

📄 [src/composables/useAuth.js](./src/composables/useAuth.js)

### 12.1 Token 存储位置

前端使用 **浏览器 localStorage** 存储：

| Key | 存什么 |
|-----|--------|
| `wc_token` | JWT token 字符串 |
| `wc_user` | 用户信息 JSON 字符串 |

### 12.2 登录流程（前端视角）

```
1. 用户在 Login.vue 填写 username + password
2. 点击登录 → handleLogin()
3. 调用 useAuth.login({ username, password, remember })
4. 发送 POST /api/user/login
5. 后端返回 { code: 200, data: { token, userId, username, nickname, avatar } }
6. 前端解析 token，写入 localStorage['wc_token']
7. 前端写入用户信息到 localStorage['wc_user']
8. 路由跳转到首页 /
```

### 12.3 登出流程

```
1. 前端清空 localStorage 里的 wc_token / wc_user
2. 调用 POST /api/user/logout（使后端 Redis 里的 token 失效）
3. 跳转登录页
```

### 12.4 前端是如何带 Token 的

在 [src/api/index.js](./src/api/index.js) 的请求拦截器里：

```js
// 每次请求前自动执行
config.headers.Authorization = `Bearer ${token}`
```

**后端需要做的：** 从 `Authorization` 请求头里解析 `Bearer <token>`，然后验证 token 是否有效。

## 13. 前后端联调常见问题排查

| 问题 | 可能原因 | 排查方式 |
|------|---------|---------|
| **接口 404** | 代理 target 不对 / 后端路径写错 | 打开浏览器 DevTools → Network 看实际请求 URL |
| **接口 401** | Token 过期 / 未登录 / 后端解析失败 | 检查 `Authorization` 请求头是否正确、token 是否过期 |
| **接口 500** | 后端 DTO 字段对不上 / 数据库异常 | 看后端日志 + 前端传的 Body 字段 |
| **跨域（CORS）** | 生产环境未配 CORS | 后端加 `@CrossOrigin` 或网关层加 CORS 配置 |
| **图片/头像不显示** | `/uploads/` 路径代理没配 / 后端静态资源未映射 | 检查 vite.config.js 的 `/uploads` 代理 |
| **响应格式前端解析失败** | 后端返回不是 `{code, msg, data}` 格式 | 统一返回格式 |
| **SSE（实时通知）连接不上** | 后端未实现 SSE / 代理配置问题 | 单独测试 `/api/notifications/subscribe` |

## 14. 后端开发快速检查清单

- [ ] **登录接口** `POST /api/user/login` 能返回 token
- [ ] **所有需要登录的接口** 能解析 `Authorization: Bearer <token>`
- [ ] **未登录返回 HTTP 401**，前端会自动退出登录
- [ ] **统一响应格式** `{ code, msg, data }`，`code === 200` 为成功
- [ ] **Vite 代理 target** 指向后端实际地址（默认 `http://localhost:8080`）
- [ ] **分页接口** 支持 `page`、`size` 参数
- [ ] **文件上传** 返回可访问的 URL 路径（如 `/uploads/xxx.jpg`）

## 15. 一句话速查手册

> **"前端写 `http.xxx('/yyy/zzz', data)` → 后端接收 `METHOD /api/yyy/zzz`，请求体 JSON 是 data，响应返回 `{ code: 200, msg: '', data: ... }`。"**

只要遵守这个约定，前后端联调基本就没问题了。
